# 研究自主推进政策

角色与effort采用当前单处配置，按任务和能力可更新；独立完整任务受实际槽位、内存和累计预算约束。现有运行不中断，不为token或方法管理新增平台。机主2026-10-13已接受v3.1并授权实施，具体前瞻方法见 `docs/task-owned-research.zh.md`。

机主 2026-10-11 明确要求，永久作为会话与自动研究的工作上下文：检查自写规范，不能被流程卡死；智能调研、高效找到可信成本后收益，主动研究、创造、进化，必要时改规则。

## 适用范围与优先级

- 本政策解释研究流程的适用性，优先于 AGENTS、skills、连续性文档及旧 prompt 中泛化的重复审批要求；不构成资金、训练、设备或订单的新授权。
- 已封存旧 scope、brief、一次性槽位、失败记录、已消耗额度保持原样。新运行依据本政策及原有效授权组织，不逐项向机主重新问许可。
- 规则服务于尽快得到可信、可执行的近期净收益证据。先复用新鲜原始来源、现成实现与负实验；新方向或关键设计决定仍先调研原文和反证。
- 选题和验收按 `docs/research-mission.zh.md` 的“选题与组合价值”：公开成果优先、复现/适配分开、研究对象包含因子/数据/模型/择时/执行、以组合增量判断。机主10-11最新确认深度优先，必要时重排周数量；有依据的多日连续研究交每日实证里程碑，不因跨日被拒绝。重大研究理解与用途差异主动和机主对齐，普通技术动作继续自主。
- 审查只保护实际涉及的范围。来源未获经济准入，不等于已批准的来源工作不能做；准备完成也不等于模型、回测或收益已获准。

## 不可绕过的实质边界

- 不编收益、不用流程通过冒充 Alpha；真实数据、PIT、成本、完整试验暴露与负结果必须保留，缺评估则绩效 N/A。
- 已看 OOS 不能重新变成未见数据；历史阈值、窗口、选择规则及冻结结果不回改，不重置失败分支或耗尽额度。
- 机主明确的资金/消费/资源上限、券商与生产权限保持。2026-10-11 16:39 UTC 机主纠正：合适的已有资源可恢复研究训练/optimizer，不存在持续全平台训练暂停。当前授权见 `reports/research/control/owner-compute-hold.json`；GRPO仍须当前有效新闻/事件研究范围、输入、manifest和剩余额度，不复活已撤回实验定义或重置消耗。
- 保留 Linux 约 500 MiB 机主余量及现有 kernel/project caps。Hadan 仅在线且新鲜 remote preflight 确认 ready、usage_ok=true、占用严格低于 50 GiB 时做获准研究，包括资源适合的训练，全部在 C:\paseo；不唤醒、不恢复、不绕设备开关。
- Hadan随时可被机主pause/关机，日历只是可用概率。复用原生checkpoint/已完分片及固定配置/种子/版本，回连fresh ready后先查旧job；支持则resume，不支持就同定义重跑，累计消耗不清零。可恢复中断保留唯一完整点，核验回传/完成或放弃后清理；失联不声称已保存或已停，不新建复杂恢复平台。
- live paper 代码仍按原 worktree/独立审查/交互合并路径；本政策不改变订单授权、有效期、caps 或 stop rules。

## 先分流，再审查

### 随能力与证据演进（机主2026-10-11再次明确）

- 这套项目是随模型、harness与可用资源进步而演进的研究工作台。流程是可修订的工作方法，不是固定技能串联或唯一道路；研究者应主动识别并删减、合并、替换已经无效或不合算的自加步骤。
- 鼓励提出和采用更好的方法、工具与实验组织。写清旧做法的问题、替代方法和一个能判断改进的结果即可，优先复用当前brief/决策记录；不为改变流程再造多层审批流程。影响经济定义时保留与问题相称的独立反方检验，不把固定表格数量当科研质量。
- 先投入能改变投资/交易判断的研究。回测引擎、数据处理、持仓/成本接口等基础能力有复用价值时可以认真建设；每项新研究不应重造引擎、runner、守护器或防御性框架。效率改造以实际省时或解除共同瓶颈为证，不以新增规范为成果。
- 新模型或harness能力出现后，按真实能力和收益问题调整委派、并行与验证方式；既不固守旧模型假设，也不因新工具出现自动迁移全部工作。规范和代码应持续维护，不能承诺某个实现永远适用。
- 方法可以升级，原始证据、已见数据与既往结果保留原口径；费用、设备、交易等仍依机主当时有效授权。必要的实质检验服务于可信收益，不扩展为对一切动作的预防性限制。

- **完整独立经济深度审查**：仅用于新经济假设、关键科学定义变化，或真正超出原批准研究范围的工作。关注原文忠实、足够经济深度、功效、基线/安慰剂、真实成本和组合边际；作者与 reviewer 独立。
- 关键科学定义包括信号/标签/模型角色、候选选择、验证分区、交易时点、成本及成功标准；改变它们须先形成新实验定义和适用审查，不能当普通 bug 修复。
- **常规执行/恢复**：已批准来源的续采、既定准备、同语义代码/路径/日志/接口修复、预算内重试和批量执行，复用完整批准包；只验必要差异、现场资源条件与真实结果，不重复十一项经济审查。
- **治理文档修订**：检查指令冲突、实际问题、变更范围与保留边界；不套经济十一项，不要求收益曲线或另建治理框架。
- scope 内合理分批、断点、运行次数或并发调整，在累计上限与资源准入内不因目录/命令变了就重审。改变科学定义、增加总额、越权或原合同明确限定的范围则先停该部分，完成对应审查/授权。
- review 通过只授予其明确范围；不能代替机主的必要授权，也不能跳过适用的 direction/iteration/knowledge/campaign、数据与 promotion 门。

## 一个完整包通过后执行到底

- 开始时一次写清可判定问题、已有批准和证据、输入/输出、累计预算与已用量、关键依赖、恢复分支、验收和停止条件；复用现有 CLI、引擎、capped 工具与短状态入口。
- 通过完整包后，连续完成必要准备、实现、实际运行、结果验收及下一条可执行动作，不以“已写申请”或“已收到 review”作为交付。
- 普通变更由作者实施、父轮验差异和结果；只有决定性变化才送相应独立复核。明确尚未满足的原 review 条件须兑现，不能悄悄忽略。
- 派工列出的主要产物目录不是同任务必要工件的逐文件许可清单。经唯一 owner/冲突检查，作者可创建并绑定本任务所需的标准来源卡、scout、canonical dossier 和 CLI 回执（包括 `reports/harness/source_cards/` 中独占命名的新文件）；路径表示修补连续完成，不因最初目录清单未列出而停等。不得借此覆盖其他 owner 的文件、生产代码、历史冻结结果或扩大科学/资金范围。
- 新运行以累计请求/运行时间/费用/试验暴露及明确重试上限控制资源，包含失败和中断；不自加“一次启动失败就永远不可恢复”的槽位，也不为每个小 bug 新造 controller。
- 使用可恢复断点、唯一 owner 和去重；恢复前确认旧进程结束、已完成输入和剩余预算。未知消耗按可信上界保守计账，不能删除 marker、换 owner 或换目录来重置额度。
- 独立任务按实际槽位与既有资源准入并行；消息只传决定性变更，进度从小状态读取。新聊天不停止无关研究；缺条件只阻塞对应线。

## 按错误类型恢复

- 路径、接口、日志或序列化等同语义错误：在已授权代码范围内修复，验证受影响路径，接断点执行。
- 可判定的 DNS/TLS/瞬时网络错误：保持来源与证书验证，按已有许可退避并有限重试；逐次计账，不改变来源或数据语义。
- OOM/超时：先核实旧进程退出，按原累计资源额度减批/分片/接断点；不抬全局内存或费用上限，不缩科学深度冒充完成。
- 数据不完整、schema/PIT 或科学语义不一致：保留原件与失败证据，隔离坏输入；语义改变先立新定义，不能用 fixture、当前成分或缓存替代真证据。
- quota 耗尽、未授权付费、训练 hold、worker paused/offline 或权限缺失：立即停止对应动作，不盲重试、不猜 reset、不换 key/provider 绕过；其他可执行线继续。
- 需机主决定时，立即列清具体事项、已耗/剩余额度、证据、可选动作及代价；不要求机主重新批准已有范围内的技术修补。真实外部限制不会因等待而自动解除。

## 方法与成本可以进化，历史证据不能改写

- 若新证据支持必要的方法或成本变化，先写明依据、与旧定义的差异和新的可证伪实验；适用独立审查及原用户边界仍有效。
- 新实验另立版本，记录继承的信息与已看窗口；选用真正未触碰的评估数据，不把旧 OOS 重新标为 frozen unseen。不得事后放宽旧门槛、重算后覆盖旧结论。
- 深度按主张所需的证据、功效和机制覆盖选择；新计划的三点曲线只是设计示例，预算是上限。浅层无效不能全面否定机制，not_at_depth不自动要求继续投入。可以依据机会成本、输入限制或反证暂缓/停投并保留未解决主张；已有冻结结论按原标准解释。任何时候都不得突破预算或设备边界。
- 可以按原始结果更正错误摘要、推论或refuted标签，保留原记录及更正理由；原始观察、已见信息和累计消耗不删除。组织agent的prompt维护不自动变成经济立项，信号/标签/特征生成prompt变化则核对实际科学影响。
- 在授权范围内自主更新技能、prompt、工具与分工，包括有理由的较大重构。只为重要且净收益不明的变化做相称比较，同时检查退步；不预设精简方案获胜、不强制每次三臂评测或真实试用。回滚只撤本次差异，保留并发修改与当前授权。

## 验收与永久记忆

- 以真实解除依赖、有效成本后结果、执行证据及耗时判断产出；报告数、审查数、hash 数与自评仅是流程记录。
- 检查随改动范围：纯 MD 做范围/差异/链接一致性核验；代码做受影响行为的必要验证，生产隔离要求保持。不把全仓测试当每个小修复的通用前置条件。
- 保留必要 before 快照、真实失败、修改理由和差异 hash；复用现有交接，不重复同义摘要、测试套件或多层控制器。
- 每次会话先读本政策，遇到规则阻碍先判断是否实质边界；对自加流程用证据主动窄修，不以“规范不允许”结束已授权工作。

## 从多路线学习到持续深挖（机主2026-10-13）

选题不能先锁定两个熟悉任务再找理由。把旧实验中的有效发现、未解释现象、近年高表现研究与未做过的经典机制一起比较，优先高潜力和强可信证据；年份、现成代码和沉没投入不代替判断。回看原始结果而不只读refuted标签，区分特定实现/组合失败与机制被否定；原失败不抹掉，错误摘要可有证据地纠正。探索与深入并行，有信息量的诊断用于选择下一实验，强来源未复现应查差异；浅测不足以否定。一个完整任务owner可在有效科学范围与累计预算内连续提出、执行和解释下一实验，不能退化为固定命令执行员。新科学分支按适用计划/候选暴露/分区/预算审查，旧已看窗口和冻结标准不重置。多试不等于无差别扫参数，深挖对象根据真实增量和反证更新。
