# 提案：把策略研究核心改成"人在环中的 LLM 研究循环" — 2026-09-15

> 性质：**提案，不是决定。** 一行代码都还没写。你看完以后说"按 B 做 / 改哪里 / 不做"。
> 读者：不需要项目背景。先说我推荐什么，再把几种做法摆在一起比。

## 0. 一句话

我推荐的做法是：**不改现有内核和策略文件格式，先用"文件 + 会话纪律"跑两轮人机共研循环，你每轮花十分钟审假设卡；
两轮跑顺了再把重复动作固化成三个小命令；两三周后用产出质量决定要不要更进一步。**
不做无人值守的自动迭代（你已明确：目前是 human in the loop，不用 cron 做研究迭代）。

## 1. 为什么要改，以及改动必须满足的约束

为什么改，已在 `docs/answers-iteration-intelligence-llm-quant-2026-09-15.zh.md` 第 1 节写明：现有研究内核是一台实验执行机，
判断只发生在我写 Step 计划的那一刻，知识库没人读，方法由计划写死。

改动必须满足的约束（这些不是可选项）：

| 约束 | 来源 |
|---|---|
| 人在环中：每批假设先给你看，你不批就不跑 | 你今天的话 |
| 不用 cron 做研究迭代 | 你今天的话（模拟盘下单的定时任务是另一回事，照跑） |
| 诚实在代码里：点时数据、带隔离期的滚动验证、成本、打乱标签占位、多重检验的试验计数 | 项目一贯规则，已有实现 |
| 机器只有 4 GB 内存，重活要限内存、可断点续跑；5 小时用量上限 | 环境 |
| 数据优先级按你的三层：内部人/新闻/空头利息 > 价量派生 > 纯技术指标 | 你 9/11 的框架 |
| 方法选择要有出处（知识库或文献），不是我拍脑袋 | 你今天的话 |
| 不能再造一层没人用的脚手架 | 你 9/11 的批评 |

## 2. 我推荐的方案（B：会话内的人机共研循环）

### 2.1 角色

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| 你 | 定方向、审假设卡、否决、拍板进模拟盘和实盘 | 不需要看代码和回测细节 |
| 我（Fable） | 读知识库、联网调研、写假设卡并给方法出处、读结果写复盘、维护《当前判断》、用人话汇报 | 不自己给自己打分：每条结论必须附对照数字 |
| 执行者（Codex/Sonnet） | 只跑已批准的卡：改配置、跑内核、产出报告 | 不选题、不改假设 |
| 代码（现有内核） | 诚实的实验室：回测、门槛、占位、试验计数、账本 | 不决定下一步 |

### 2.2 五个产物，全部是文件，git 可追踪

1. **知识库摘要层** `reports/research/knowledge/digest/`：把现有 60 条实验账本、64 条经验记忆、211 条文献来源压成每条不超过 300 字的条目：
   主张、证据数字、来源（账本 id / 来源卡 / URL）、状态（支持 / 被否定 / 未测）、最后更新。
   为什么需要：现在的索引和账本原文合计 77 万字节，直接读一遍要二十万 token，没法每轮读；摘要层每轮读一两万 token 就够。
   这是最大的一次性工作，估计一到两天（我定格式和抽查，执行者批量生成）。
2. **《当前判断》** `docs/current-view.zh.md`：常设一页。目标、我们现在相信什么有效、什么已被否定（带数字）、排好序的下三个假设、需要你决定的问题。
   每轮更新，你只需要读这一页。这是解决"在我说之前你都不会自己去思考"的机制：它必须每轮更新，偏了你一眼能看见。
3. **假设卡** `reports/research/hypotheses/H-日期-序号.md`：一张卡回答：要验证什么、属于哪一层（选股/择时/信号接受/组合）、用哪层数据、
   预测什么目标、用什么方法以及**为什么**（必须引用摘要层条目或文献）、预期看到什么数字、**什么结果算否定**、占位对照怎么做、
   记入哪个假设族的试验计数、预计成本、状态（提出 / 你已批准 / 运行中 / 完成）、你的批注。
4. **实验运行**：走现有内核（`run_experiment` 的配置对象或一份策略文件），不改。已有的门槛不再是"许可"，而是每次必报的字段。
5. **复盘卡** `reports/research/lessons/`：结果对比预期、哪条信念变了、更新了哪几条摘要、下一步。摘要层和《当前判断》由它驱动更新。

### 2.3 一轮怎么走

1. 我读摘要层和《当前判断》，需要时联网查文献，写出 3 到 5 张卡，按"预期能学到多少 × 你的数据层级 × 成本"排序，发给你。
2. 你花约十分钟：批准、否决、或改。**不批准的卡不跑。**
3. 执行者跑批准的卡。日线、500 只股票的一个单元是分钟级，大头是面板构建，限内存分批跑。
4. 我读结果，写复盘卡，更新摘要层和《当前判断》，用人话告诉你结论和下一批卡。
5. 任何候选要进模拟盘或实盘，单独找你拍板。

一周能跑三到四轮（会话驱动，不是定时）。

### 2.4 方法怎么选，才算"LLM + 知识库 + 调研"

每张卡的"方法"一栏必须写出处：摘要层里哪条经验、哪篇文献支持这个方法适合这个问题。没有出处的卡不合格。
需要新文献时，先跑一轮小预算的联网核实（像今天那两份核实报告一样，标明已打开 / 仅摘要 / 未核实），再写卡。
不做自动的进化式搜索或大网格：试验数一多，多重检验的代价会把回测吹起来。每个假设族有试验预算，卡上写清用掉多少。
卡与卡之间先做一次便宜的"回测前排序"（我让几个不同角度的论证互相反驳，再排序，借自 Google AI co-scientist 的辩论加 Elo 机制），
但这种排序只用来决定先跑哪张卡，永远不用来判定"这个策略行不行"，后者只能由你定义好、我改不了的回测数字来判。
每张新卡还要写明它和已有卡、已有账本条目的区别在哪（借自 AlphaAgent 的"原创性正则"），挡住"同一个想法换个写法再试一遍"这种变相重复试验。
每张卡只改一处：一个数据层、一个目标或一个模块，不整份重写策略（借自 Google MLE-STAR 的"定向精炼"），这样你审得动，试验计数也算得清。

### 2.5 诚实机制：已有的和新增的

已有（代码里）：点时股票池、带隔离期的滚动验证、成本模型、打乱标签占位、DSR 试验计数、门槛结果全部入账本。
新增（先是卡的填写规则，跑顺后再变成校验代码）：
- 每张卡必须写否定判据和占位设计，否则不能批。
- 每个假设族维护试验计数，卡上记入；DSR 用族的计数算。
- 同一批价量特征上不再开新的模型格子，除非换了数据层或换了目标（写进卡的校验）。
- 复盘必须报 SPY / MTUM / SPMO / 同波动超额 / 占位这五个对照数，缺一不算完成。
- **评分函数和门槛的定义只有你能改，我和执行者都不能改**（借自 DeepMind AlphaEvolve 的分工原则：人定义"要什么"，机器找"怎么做"）。一旦提假设的一方能动评分，循环里所有数字立刻失去意义。
- 试验计数不是文书，是数学前提：Deflated Sharpe 需要"独立试验次数"和"各次夏普的方差"才能算，PBO 评的就是"选择过程"本身。一个不数自己试了多少次的循环，事后永远补不回一个可信的夏普。

### 2.6 成本

| 项目 | 估计 |
|---|---|
| 摘要层初建 | 一到两天（我 + 一个执行者） |
| 每轮我读写 | 三到六万 token |
| 每轮执行者 | 每张卡五到三十分钟机器时间 |
| 每轮你 | 约十分钟 |
| 新代码 | 前两轮零；之后约三个小命令（建/更新摘要、新建/校验卡、写复盘） |

### 2.7 两三周后怎么判断它值不值

- 它提出并跑完的候选，在同波动 SPY 超额和最大回撤上，是否好于旧流程的最好成绩（超额 -3.4%，连接候选 -11%）。
- 方向级纠正是否不再靠你提醒：数一数你每周提出的方向纠正次数，现在大约每周两到三次。
- 每轮实际成本是否在上表以内。
三条里两条不达标，就停掉，退回方案 A。

### 2.8 可逆性

全部是文件和最多三个命令，不碰模拟盘下单链路，不碰内核，随时停。

## 3. 对比分析：四种做法

| 维度 | A：不改结构，只改我的工作纪律 | **B：文件 + 会话循环（推荐）** | C：自动调度循环（RD-Agent 式） | D：全面替换研究核心 |
|---|---|---|---|---|
| 改什么 | 什么都不建；我每个会话手动读、提、跑、学，维护《当前判断》 | 摘要层 + 《当前判断》 + 假设卡 + 复盘卡；内核不动；跑顺后三个小命令 | B 的全部，加上程序自动排卡、分配算力、无人值守跑 | 策略文件格式降为管道容器、旧门槛文书退役、研究内核重写为循环 |
| 工程量 | 零 | 一到两天初建，之后很小 | 再加一到两周 | 三到四周，期间研究基本停 |
| 你的参与 | 靠我自觉，你看不到机制 | 每轮十分钟审卡 | 每天看摘要，可否决 | 前期几乎全在做工程，你看不到候选 |
| 方向纠错速度 | 取决于我，容易回到老样子 | 一轮之内（几天） | 一晚之内 | 建成前不变 |
| 脚手架风险 | 无 | 低：前两轮零代码，只固化证明有用的 | 中：调度和自动化本身就是脚手架 | 高：这正是你批评过的模式 |
| 多重检验控制 | 靠我记 | 卡上记试验族预算，复盘必报占位 | 自动跑容易失控，必须硬编码预算 | 可以做好，但要重写 |
| 符合"人在环中" | 是 | 是 | 否（你已说目前不要） | 取决于设计 |
| 可逆性 | 完全 | 完全 | 中 | 低 |
| 两三周能看到什么 | 几份更好的报告 | 六到十张卡跑完、一份持续更新的《当前判断》、一到两个新候选 | 更多卡，但审不过来 | 主要是代码 |

为什么不选 A：它和过去三周没有区别，你已经看到结果。为什么不选 C：你明确说目前要人在环中；而且自动化应该固化的是"已证明有用的动作"，现在还没有。
为什么不选 D：风险最大、最像再造一层结构，而且期间研究会停。B 是 A 到 D 之间成本最低、最快能看到结果、随时可退的一步；C 和 D 保留为 B 跑通后再议的方向。

## 4. 如果你同意 B，分阶段怎么走

| 阶段 | 内容 | 你看到什么 |
|---|---|---|
| 第 0 轮（本周剩余） | 建摘要层；写《当前判断》第一版；出第一批 3 张卡 | 一页《当前判断》 + 3 张卡，等你批 |
| 第 1 到 2 轮（下周） | 跑批准的卡，复盘，更新 | 每轮一份人话汇报 |

第一批卡我会建议的方向（只是建议，卡出来你再看）：内部人 Form 4 作为动量组合的确认门；2024 年起的新闻点时包做成截面文本特征；
给现有规则信号加元标签仓位分档。三者都在你的一级数据层或"规则在前唯一正当的位置"上，都用免费或已有数据。

## 5. 需要你看的三点

1. 同不同意按 B 走，还是要改成别的组合。
2. 每轮你愿意花多长时间审卡（我按十分钟设计；如果更少，我就每轮只发一张最重要的卡）。
3. 第一批卡的方向是否同意上面三条。

## 6. 参考了哪些循环设计、借了什么、没借什么

后台核实了 16 个系统的循环机制，每条带 URL 和访问日期，写在 `reports/research/control/research-loop-designs-survey-2026-09-15.md`
（15 次联网调用，部分只到摘要级，文件里逐条标了已打开 / 仅摘要 / 未核实）。下面是提案里每个设计点的来源。

**借了的（对应到本提案的位置）：**

| 借用点 | 来自 | 落在提案哪里 |
|---|---|---|
| 人定义"要什么"（评分函数与护栏），机器找"怎么做"；agent 不许改评分 | DeepMind AlphaEvolve / FunSearch | 2.5 最后两条 |
| 副驾驶模式 + 预定检查点，人在每个阶段给反馈能显著提升质量（有对照结论） | Agent Laboratory；Alpha-GPT 2.0 把人机协作当核心目标 | 2.3 第 2 步：不批不跑 |
| 研究 / 开发 / 反馈三角色分开；提假设的不能给自己打分 | 微软 RD-Agent(Q)；FITEE 2025 综述的 miner / evaluator / assistant 分类 | 2.1 角色表 |
| 假设写成可被推翻的形式：预期结果 + 否定判据，结果出来后强制回判 | 由 AlphaAgent 的"假设与因子一致性"正则推广 | 2.2 假设卡字段 |
| 原创性检查挡"换皮重复试验"，复杂度约束挡过度工程化 | AlphaAgent（KDD 2025，摘要里明确点名过拟合） | 2.4 |
| 定向改一个模块，不整份重写 | Google MLE-STAR（在 MLE-bench 上把 AIDE 的奖牌率从 25.8% 提到 43.9%） | 2.4 |
| 回测前用辩论和 Elo 给想法排序，便宜且不消耗样本 | Google AI co-scientist | 2.4 |
| 只追加不删改的记录，下一轮必须引用，并强制计数试验 | QuantAgent 的"新洞见写回知识库"外环；数学依据是 Deflated Sharpe 与 PBO | 2.2 复盘卡、2.5 |
| 把严谨性当成模块设计，而不是当文档 | Curie | 2.5 整节 |
| 挖掘层与组合层分开，组合权重可随时间变 | AlphaForge（AAAI 2025） | 4 里的候选方向（选股与组合分层） |

**刻意没借的（以及为什么）：**

| 没借 | 来自 | 原因 |
|---|---|---|
| 用多臂老虎机自动分配算力、无人值守加速搜索 | RD-Agent(Q) | 它的摘要里没有任何过拟合或多重检验控制；老虎机的作用恰恰是更快地朝"回测更好看"的方向多试。你也明确说目前要人在环。留作 B 跑通后再议（方案 C） |
| "全自动、无人参与"的定位 | Chain-of-Alpha | 与人在环冲突 |
| 用"论文被接收"或 LLM 辩论分数当成功判据 | Sakana AI Scientist v2、AI co-scientist | 接近自评。只能用来排想法，不能判策略 |
| 把进化搜索或树搜索直接挂在回测指标上 | AlphaEvolve / FunSearch / AIDE | 它们成立的前提是评估器便宜、快、难被钻空子；金融回测三条都不满足，照搬等于自动化地制造过拟合 |
| 无模板的自由代码生成、宽树搜索 | AI Scientist v2、AIDE | 这台机器 4 GB 内存且内存杀手优先杀 agent 进程，搜索宽度和代码自由度必须先设上限 |

**这轮没核实到、下一轮要补的：** RD-Agent 的知识库到底怎么存、怎么被下一轮引用（正是我们最想借的部分，只到摘要级）；
一篇题为《Profit Mirage：重审 LLM 金融 agent 的信息泄漏》的 2025 年论文，直接关系到循环的诚实性，还没读；
各开源仓库的许可证。
