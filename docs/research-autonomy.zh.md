# 自主研究与当前待办 — 2026-09-21

目标以 `docs/research-mission.zh.md` 为准。用户已委托日常研究，旧的“方案 B 是否批准、每轮看几分钟、每张卡等审批”不再阻塞联网、草稿、修复和有效预算/合同内的实验。模型不会因为一句“记住”而永久可靠；本项目使用共同规则、每轮提示、来源证据与标准入口检查共同维持目标。

## 已实现和仍未启用的部分

`uv run oc research autonomy-tick` 默认只检查状态，不调用模型。
`uv run oc research autonomy-tick --execute` 也只有在 `config/research-autonomy.json` 启用且明确填写预算后才派一个任务。

控制器使用单个 Claude 引擎，复用本地额度读数；日预算和滚动 5 小时预算使用绝对 fresh token 数，另留交互会话额度。它们是本地记录的软限制，不是订阅容量的准确百分比。按每任务上限提前保留预算；失败或崩溃不把未知消费退回预算。未知/无效计量、有效 429、任务超时、交互余量不足时暂停；同一时刻一个 worker，完成任务不再运行，遗留 started 必须核对日志后处理。

已准备两类任务：

- `scout`：Claude 只能读取和联网搜索，结果落日志；没有 Bash/写文件工具。它提出下一步，不能执行来源中的命令或自行扩大预算。
- `registered_experiment`：只运行本地配置登记并绑定脚本 SHA、候选 manifest SHA 和 iteration 的命令；先过方向检查及原有 iteration 检查。它不是通用 shell 调度器，也不是任意 Python 的安全沙盒；登记命令前仍需审查其行为和完整依赖，禁止 broker 写入。

模型输出不会自动变成命令或新增试验。当前版本能无人值守消费已经登记的有界任务队列，**尚未实现未经核验的新提案自动变成完整训练任务**；那一步仍需把提案编译成有效研究合同和候选清单。首个队列任务是一次有界情报更新；不重复无穷搜索。队列完成后空闲，只有新证据/已登记下一阶段才增加任务。

`deploy/research/` 已提供 systemd service/timer，每次结束 10 分钟后再检查。它们尚未安装或启动；预算配置 `enabled=false`。可以全天待命，不意味着全天消耗模型。当前没有新增后台模型账单。

## 怎样防止方向检查变成另一份空文书

新建 iteration 自动生成 `direction-review.json`。其中需要目标与市场窗口、现成方案比较、尚缺的证据、历史反例、成本、最便宜的可否定测试和计算上限。

每条来源绑定查询记录、实际打开的 URL、抓取时间、本地快照及 SHA-256、verified source-card claim 与快照中存在的短引文；未检索到第三方复现就写 unknown/未找到，不能伪造。`oc research direction-check <path>` 可单独验证，`oc research iteration validate <id>` 同时执行。

现有冻结档案按 `config/research-direction-legacy.json` 的文件哈希保留原合同。新 ID 或被改动的档案不能靠将 brief 改回 schema v2 绕过方向检查。最终历史报告不会只因为时间过去而要求当时的来源重新变“新”。这些检查验证证据关联和完整性；真实性及策略适用性仍需要阅读原文和反证，不能仅凭自由填写的 JSON 证明利润。

## 方向顺序及依据

本轮实际打开了 FINRA 官方说明、BJZ 原文、Qlib 官方代码、SPMO 产品页和第三方跟踪 FAQ。证据见 `reports/research/intel/I-20260921-01-profit-first-direction.md` 及其来源卡。官方代理能力依据另见 `reports/harness/source_cards/research_autonomy_20260921.jsonl`。

优先现有 ETF 的冻结后执行与净结果，因为离可执行收益最近；FINRA 只配一次便宜的增量检验，因为场外汇总与论文私有订单不是同一数据；Qlib 先查语义和资源，再考虑一个固定模型，因为训练再多次也修不好标签误解。这些是依据当前证据的投入顺序，不是盈利承诺或晋升结果。

## 补充的短期机会地图

`reports/research/intel/I-20260921-02-near-term-alternatives.md` 进一步核对了异常放量个股的 ORB 与财报文本事件。新增研究优先做 ORB 的历史股票资格、未复权/复权单位和同分钟入场止损顺序检查，复用原论文与 QuantConnect 代码；PEAD 先核对公开—抓取—特征—下单时钟。现有 ETF 前向证据可以独立继续积累。FINRA 定义核对已经做完，不重复搜索同一问题；Qlib 不因代码已经写了就优先于更接近短期机会的方向。

这份补充不宣称近期盈利：QuantConnect 的约 2.4 Sharpe 仅来自 2016 单年；EAR-AI 本次只取得作者摘要，缺完整成本/代码/独立复现。新方向先过数据可行性检查，失败就 dependency_skipped，不启动盲目参数或模型网格。
