# Step 17：模拟盘重新开跑（低于合同的"执行彩排"）— 2026-09-15

> 读者：不需要项目背景。先说结论，再说细节。

## 1. 一句话结论

模拟盘已经重新开跑。**2026-09-15（周二）UTC 07:47（美东 03:47）**，系统把
`us_recent_high_return_top50`（"近期高收益动量前 50"）这只候选策略的目标持仓，
变成了 Alpaca **模拟盘**（Paper，假钱）上的 50 笔"开盘集合竞价市价单"，券商已全部接受，
预计 **2026-09-15（周二）美股 09:30 开盘成交**，合计约 92,640 美元。
从今晚起，每个交易日 UTC 23:30（美东 19:30）自动重复这一步，只发"目标和现状不一样"的单。

## 2. 用的是什么策略、为什么是它

- 策略：每周五收盘后，在成交额前 500 的美股里，按"过去 12 个月动量 ÷ 过去 3 个月波动"
  排名，买入前 50 名，每只 2%，满仓，周一开盘调仓。规则策略，没有机器学习。
- 为什么是它：它是目前唯一"研究链条完整、目标持仓每天自动生成、数据到位"的候选。
  其它候选要么还在研究，要么根本没有连到下单链路。
- 它的成绩**不合格**（诚实写在这里，也写进每一份产出文件）：2024 年至今回测
  总收益 +33%，最大回撤 -28%，和"同波动率的 SPY"比是 **-11%**。合同门槛（gate v2）没过。

所以这次不是"策略上线"，是 **"彩排"**：目的是把"目标持仓 → 下单 → 成交 → 成交成本分析"
这整条 50 只股票的链路，在假钱上真的跑一遍并测量它，不是证明策略赚钱。
每份文件都打了 `rehearsal=below_contract`（低于合同的彩排）标签，避免以后被误当成推广证据。

## 3. 为什么不用旧的下单链路，而是新写了一条

旧的模拟盘下单链路（`oc run paper` → 就绪检查 → 金丝雀授权）是为 1~2 只 ETF 的
路由策略设计的：单笔上限 1,000 美元、每晚最多 4 笔、必须先有"推广报告合格"。
一个 50 只股票、10 万美元的组合根本装不进去，而且它连 `model_ranking_portfolio`
这种组合模式都不认识。硬改它要碰十几个文件，本周做不完也没必要。

新链路只有一个文件 `open_composer/paper_rehearsal.py`（约 700 行）+ 3 个命令 + 10 个测试。
安全性靠代码而不是靠文书：

| 安全属性 | 做法 |
|---|---|
| 只能是模拟盘 | 复用已有的"严格 Alpaca Paper 客户端"（校验域名和沙盒标记）；授权文件绑定模拟盘账户哈希，换账户即失效 |
| 必须有明确、会过期的授权 | `reports/paper/rehearsal/us_recent_high_return_top50-authorization.json`，14 天到期（2026-09-29），绑定策略文件内容哈希（改了策略就要重新授权） |
| 有硬上限 | 总仓位 ≤ 100%（不加杠杆）、单只 ≤ 5%、每晚 ≤ 150 笔、每晚 ≤ 15 万美元、授权期内累计 ≤ 75 万美元 |
| 一键停 | 全局 kill switch 打开则一笔都不发；也可以撤销授权 |
| 不重复下单 | 每笔单有固定的 client_order_id（策略+交易日+代码+方向），同一晚重跑不会再发 |
| 先记录再下单 | 每笔单先写信号日志 `signal_logs/paper-rehearsal-us_recent_high_return_top50.jsonl`，再提交 |
| 只在允许的时间窗发 | 只发"开盘集合竞价"单（time_in_force=opg），只在美东 19:00 之后到次日 09:28 之前提交 |
| 只买卖、不做空 | 持有但不在目标里的先卖，目标里缺的再买；先卖后买 |

## 6. 怎么停

```
uv run oc paper kill-switch --enable --reason "原因"          # 立刻停一切模拟盘下单
uv run oc paper revoke-rehearsal strategy_specs/drafts/us_recent_high_return_top50.yaml --reason "原因"
```
把 crontab 里 23:30 那一行删掉也可以。停了以后已成交的持仓不会自动卖出，需要手动处理。

## 7. 本周做过的操作记录

1. 策略文件改为 **市价开盘单**（`moo_market`）而不是原来的"开盘限价 +20bp"。
   原因：回测假设每只都在次日开盘价成交；20 个基点的限价单会系统性漏掉跳空高开的股票，
   而动量策略赚的恰恰是这些。成交成本由 TCA 事后测量，不靠假设。
2. 关闭 8 月 5 日打开的 kill switch。当时的原因（TQQQ 未完成订单、状态漂移）属于**上一个**
   模拟盘账户；现在的账户已重置（账户哈希已变，10 万现金，0 持仓，0 挂单）。
3. 写入 14 天授权（授权人：用户 2026-09-15 指令，由 Fable 执行），限额见第 3 节。
4. 空跑（不下单）验证：50 笔买单，合计约 92,640 美元，单笔 1,017~1,994 美元。
5. 加入 23:30 UTC 定时任务。crontab 原文备份在 `/tmp/crontab.backup.2026-09-15`。
6. UTC 07:47 手动执行了一次真实提交：50 笔市价开盘单全部被 Alpaca 接受（状态 accepted），
   账本 `us_recent_high_return_top50-orders.jsonl` 50 行。原因：与其等到晚上让定时任务第一次
   就真下单，不如白天先跑一次、当天就能看到成交和问题；今晚定时任务会遇到"已持有 50 只"，
   应全部判为 `skip_no_change`，这本身就是第一次幂等与对账检验。
7. 紧接着又执行了一次同样的命令做幂等检验：0 笔新单（见下方状态）。

## 7b. 2026-09-16 凌晨的第一个真实发现和处置

- **发现**：9/15 开盘的 50 笔"开盘集合竞价市价单"（opg）只有 5 笔全部成交、12 笔部分成交、33 笔一股没成，45 笔在 09:30–09:32 到期作废。
  按金额只成交了 21%。Alpaca 模拟盘对集合竞价的模拟不可靠，一个 50 只股票的组合不能靠它。
- **处置**：策略文件的下单方式改为"收盘后提交、开盘执行的普通市价单"（day_market）；重新签发授权（策略哈希变了）；
  撤掉当晚定时任务发出的 45 笔 opg 单（它们会再次作废）；以新方式重新提交 45 笔，Alpaca 已接受，预计 9/16 09:30 成交。
- **顺手补的两件事**：一是"整股漂移容忍"，目标和现状只差一两股、金额不到目标 5% 时不再下单，避免每晚因参考价变动产生几十笔小单；
  二是新增 `oc paper rehearsal-reconcile`（成交对账，输出成交率和相对参考价的滑点）和 `oc paper rehearsal-cancel-open`（只撤本策略账本里的挂单）。
- **对账文件**：`reports/paper/rehearsal/us_recent_high_return_top50-fills-summary.md`（人读）、`-fills.jsonl`（逐笔）。
- **9/16 开盘结果**：改为市价单后的 45 笔全部成交（按金额 100%），组合到齐 50 只，账户约 9.99 万美元。
  相对参考价的成交价中位数低 226 个基点，参考价是周一收盘口径，不是执行质量指标；真正的执行质量要等"相对官方开盘价"的 TCA。
