>

## 1. 诊断：第四稿的首页为什么"没有主次"

第四稿 Now 屏的六块面板（账户权益、Agents 实时卡、研究队列、5 小时 token、系统刻度、24 小时模型调用 LED）每块都是"真实数据主视觉"，于是没有一块是主视觉。对照机主实际要知道的事：

| 机主的问题 | 第四稿首页给了什么 | 问题 |
|---|---|---|
| 要我做什么 | 右上角 4 个注意事项芯片（kill switch、额度、数据新鲜度、磁盘） | 多数是运维状态，不是机主能做的事；没有机主要做的决定和截止日 |
| 钱怎么样 | 共享账户权益柱状图 + 每条子策略一行起始以来收益 | 账户权益含闲置现金，不是策略表现；没有当日 / 近 5 日，没有和 SPY 比 |
| 离实盘多远 | 没有 | — |
| 研究在做什么 | 任务队列分段条 + 4 条最近任务 | 看到任务 ID，看不到三条引擎在哪一步，也看不到主审轮的判断 |
| 自动轮汇报、日报、周报 | 没有 | 只能在邮件和仓库文件里看 |

另外顶部状态条在每一屏都铺六个槽位（Claude 两条额度、Codex、fresh 5h、agent 点、data、auth），手机上第一屏被这些占掉一截。

## 2. 目标信息架构

### 2.1 导航：四个主屏，System 降级

| 位置 | 内容 |
|---|---|
| 桌面侧栏 | **Today · Reports · Paper · Research**（⌘1–4）；下方小字的 **System** 组：Agents · Quota · Health（⌘5–7） |
| 手机标签栏 | Today · Reports · Paper · Research · System（System 打开 Health，Quota / Agents 时同样高亮） |
| 状态条 | 四个主屏只显示一个 `system ok / N issues` 药丸（六个状态对象取最差）和运行中 agent 数；System 组各屏保留原来的六槽位 |
| Lineage | 从 Research 进入，不占侧栏 |

`/hypotheses` 保留为 `/research` 的别名，旧链接和锚点不失效；`/v2/` 前端 B 未动。

### 2.2 首页 `/` Today：按顺序回答四个问题

每块一个面板，顺序就是优先级，手机上从上到下同序。数据层只复用 `open_composer.reports.owner_digest`（日报的同一份 `DigestData`）和 `reports/owner/live-track.json`，网页上的数字和当天邮件完全同源。

| 块 | 回答 | 内容 | 数据来源 |
|---|---|---|---|
| **Needs you** | 要我做什么 | 一盏灯 + 一个词（OK / Attention / Problem）+ 一行原因；机主要做的事（和日报"需要你处理"同一列表）；带日期的待决定事项（截止、剩余天数，7 天内变琥珀）；运维异常折叠成一行"N operational issues · research side fixes these" | `owner_digest.owner_items`、`ops_items`；`live-track.json` 的 `owner_decisions` |
| **Money** | 钱怎么样 | 子策略合计净值（大数字）与起始以来；当日 / 近 5 日各自对 SPY；账户净值、kill switch、挂单；每条子策略一行：迷你曲线（相对预算）、当日、近 5 日、起始以来（下方 SPY 同期）；v1.2 quant1 / quant2 有对账记录后自动出现，之前一行灰字；最后一行 **Live: none** | `combined_returns`、`sleeve_returns`、`spy_returns`、`SleeveRow.navs`、`collect_book`；`live-track.json` 的 `live` |
| **Path to live** | 离实盘多远 | 每个候选一行：阶段、10 格刻度表示真实模拟会话 n/10（满 10 算够）、下一步和截止日、实盘提议日；底部一行机主定的规则 | `live-track.json` 的 `candidates`；会话数用 `owner_digest.paper_sessions_since`（与日报第三节同一函数） |
| **Research** | 研究在做什么 | 三条引擎各一行：现在在哪一步、下一步和截止日；右侧一张卡：最新主审轮汇报的标题和前 3 条要点，点开进报告页；没有轮次汇报时退回 `docs/current-view.zh.md` 最新章节；面板标题行带队列计数 | `live-track.json` 的 `engines`；`reports/owner/rounds/`；`parse_view_sections`；队列计数来自 `DigestData` |

状态词的规则（`cockpit/data/today.py::build_needs`）：**Problem** = 有东西停了（kill switch 打开、研究轮被额度闸门暂停或受限、汇报数据本身读取失败）；**Attention** = 列表里有任何东西（机主要做的事、7 天内的决定、运维异常）；**OK** = 什么都没有，副标题写 "Nothing needs you"。每日驱动报错、数据过期这类研究侧处理的问题只算 Attention，不用红灯吓机主。

### 2.3 报告中心 `/reports`

左边列表、右边阅读区；手机上列表 → 详情（详情页顶部有返回）。列表分三组、各自按时间倒序，每组默认 8 条、更早的折叠：

| 组 | 来源 | 说明 |
|---|---|---|
| Daily | `logs/owner-report/daily-<UTC 日期>.md` | 脚本生成、不进 git；标题取文件第一行 |
| Weekly | `reports/owner/weekly/<ISO 周>.zh.md` + `logs/owner-report/weekly-<日期>.md` | 按 ISO 周合并：主审轮的判断在前，脚本的数据附录在后（"Data appendix" 分隔）；只有一半时标 `judgement` / `data only` |
| Rounds | `reports/owner/rounds/<UTC 时间>-<lead|exec>.md` | 10-05 起自动轮写入；现在为空，空状态写明什么时候会出现 |

Markdown 用 `markdown_it`（commonmark + 表格 + 删除线），支持有序和嵌套列表；原始 HTML 一律转义；渲染前过 `secret_scrub`；每个路径先按种类的正则校验，再过 `safe_repo_path`，不认识的 id 返回 404。阅读区排版为长文设计：14px、1.6 行高、表格可横向滚动、二级标题带分隔线。桌面打开 `/reports` 时阅读区放"最新一份"的卡片而不是空白。

JSON 镜像：`/api/today.json`、`/api/reports.json`、`/api/reports/{kind}/{id}.json`，供 `/v2/` 或原生客户端使用。

## 3. 删掉或降级了什么，为什么

| 第四稿首页元素 | 去向 | 理由 |
|---|---|---|
| 共享账户权益柱状图（大） | Paper 页保留 | 账户权益含闲置现金，不回答"策略挣没挣钱"；首页改为子策略合计和各自对 SPY |
| Agents 实时卡、工具调用流 | Agents 页 | 机主不需要看 agent 在调用哪个工具；首页只留"N running" |
| Fresh tokens 5h、额度条 | Quota 页；状态条药丸 | 预算是研究侧的约束，出问题（受限 / 暂停）时以 Problem 出现 |
| 24h 模型调用 LED | Agents / Quota 页 | 好看但不回答任何问题 |
| 系统刻度（data / cron / disk / memory） | Health 页 | 同上；故障走 ops 行 |
| 研究队列分段条 + 最近任务 | Research 页；首页只留计数 | 任务 ID 不是机主的语言；首页改为三条引擎的"现在 / 下一步 / 截止" |
| 状态条六槽位（主屏） | System 组各屏 | 手机首屏不再被状态条占一截 |

## 4. 性能与缓存

- `collect_digest` 在本机 5–10 秒（模拟盘账本 3.6 s、健康扫描含 Modal 账单子进程 5 s）。网页侧**从不在请求路径上收集**：`cockpit/data/today.py::TodayCache` 按仓库根缓存最近一次快照，应用的后台线程启动时和之后每 5 分钟刷新一次（`_today_warm_loop`，和额度 warm 线程一样在没有 `~/.claude/projects` 的机器上直接退出，所以 pytest 里不会跑收集，也不会碰 Modal）。
- 请求路径只读缓存 + 两个便宜文件（live-track、报告索引）。预览实测热缓存 `/` 0.26 s，`/reports` 0.13 s；服务刚启动、第一次快照未落地时首页显示 "Collecting the first snapshot" 并每 4 秒自刷。
- 首页 eyebrow 写明 "data N m ago"，Money 面板写明是哪一天的收盘。
