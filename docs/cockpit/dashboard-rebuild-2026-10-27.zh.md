## 3. 视觉与文字规则

- 复用原生 `hero`、图表区域、列表、抽屉及主题令牌。Geist 用于正文、标题和主数字；数字列等宽对齐，时间与标识符按原样式处理。主数字参考桌面 56 px、手机 44 px；图表先于次要信息进入首屏。
- 使用原有冷色背景层级、细分隔线和单一强调色；涨跌颜色表达数值方向。玻璃效果限于导航、工具栏和抽屉控制区。
- 主图标签使用“累计收益率”“10万美元净值”“当日涨跌”；账户页使用“实际盈亏”“本金”等短名词。删除“已含已入账调整”“计算口径与数据日期”等解释性入口及正文长段；算法与来源留在本文和数据记录中。
- 估值时间使用实际快照时间；完整时间可在悬停或详情中查看。真实缺失显示“待估值”或“数据缺失”，历史曲线保留缺口。
- 未归属单策略的已入账现金项在账户页集中显示为“其他收支”，提供明细；数值精度造成的差异由格式化与汇总处理，不向用户铺开舍入过程。
- 保留原有导航切换、键盘关闭、浏览器返回、减少动效和手机布局规则；新增页面沿用同一套组件。

## 4. 收益与显示范围

### 4.1 主图：所选策略等权参考

设所选策略数为 `N`，策略 `i` 在日期 `t` 的累计收益率为 `rᵢ(t)`，单位为百分数。所选策略的平均累计收益率为 `R(t) = Σrᵢ(t) / N`，10 万美元参考净值为 `V(t) = 100,000 × [1 + R(t) / 100]`。例如两个策略分别累计上涨 10% 和下跌 2%，平均收益率为 4%，参考净值为 104,000 美元。每个策略权重相同，账户原有本金大小不影响权重。

“当日涨跌”使用相邻日期的参考净值变化：`[V(t) / V(t−1) − 1] × 100%`；可对应显示美元变化 `V(t) − V(t−1)`。首日没有前值、前一日或当日缺失、前值为零时，当日百分比留空。计算不跨越缺失日寻找更早的有效值。这条曲线直接平均累计收益率，不执行每日调仓，也不平均各策略的单日收益率后连乘。

时间轴从所选策略中最早的真实开始日开始，所选数量 `N` 在整条时间轴保持固定。所选策略尚未开始的日期按现金处理，累计收益率为 0%，返回 `not_started` 状态；策略实际开始后的必要估值缺失时，该策略和当日平均值均留空，计算不会临时删除该策略或缩小分母。开始日期无法确认时保留缺口。

所选策略的历史收益率使用对应历史估值与本金。F1 按绑定的账户日线、开始本金和已知按日入账的非交易现金重建交易分项，扣除截至该日的已知非交易现金后再计算累计收益率；日线或必要现金归属不足时保留缺口。历史数据与当前快照分别保留自己的时间，缺失历史不由当前值填充。

### 4.2 账户页：实际资金结果

实际美元盈亏按独立资金池核对后相加；实际资金收益率用实际总盈亏除以对应投入本金。资金注入增加本金，费用和收入按实际入账计入盈亏；同一资产或父子账本只计一次。这些实际金额不随主图所选策略变化。

现有聚合包括旧共享资金池、新六父策略资金池和 F1 实际账本；旧策略与已退出 top50 的真实贡献保留。旧池本金只计一次，新六父策略按实际分配本金计入，F1 沿用已核对的开始前本金。未分配到策略的其他模拟账户现金不增加策略本金。具体账户归属与资金依据沿用[现有聚合定义](../../reports/paper/diagnostics/fresh-dashboard-owner-audit-20261027/Main-clean-all-strategy-overview-continuation.json)。

实际策略分项加“其他收支”应与实际总盈亏核对一致。金额已有依据但本金缺失时保留金额，独立收益率显示待补；已退出 top50 因独立本金依据不足，不参加主图等权选择。账户历史按实际资金生效日期核算，并保留各自估值时间和缺口。

## 5. 策略更新与接口契约

现有读取入口为 [`/api/paper.json`](../../open_composer/cockpit/api.py)，保留 `report`、`paper_history`、`paper_overview` 和现有版本字段；`/api/paper/{strategy}.json`、旧策略详情链接继续有效。等权参考由同一份已核对的策略历史与当前快照派生，返回稳定策略身份、各日收益率、开始状态与缺失状态；主图选择只影响派生结果。策略抽屉按第 2 节列出的实际数据能力读取详情。

后续接入或修改策略按以下流程执行：

1. 在现有[策略显示配置](../../config/paper-validation-dashboard.json)登记稳定身份、名称及快照来源；运营方通过现有发布契约更新实际状态、资本、持仓和成交记录。
2. 估值生产端基于实际账本和资金关系核对分项和总计，输出现有 v1 投影。将[总览构建入口](../../scripts/build_paper_overview.py)的 `--output` 结果或同契约的已核对文件交给[发布入口](../../scripts/publish_paper_overview.py)：`python scripts/publish_paper_overview.py --input <已核对的投影文件>`。发布器校验身份、金额、收益率、日期及缺失状态，保存按内容哈希命名的快照，再原子替换[总览绑定](../../config/paper-overview-dashboard.json)。旧快照保留，原有[历史绑定](../../config/paper-history-dashboard.json)保持独立。
3. Dashboard 刷新读取同一份已发布数据。前端按返回的策略数组生成列表与计数，名称、状态和数量均不写死；已发布策略的当前收益与历史序列按稳定身份关联。
4. 新实际策略已经出现在运行记录、但估值尚未发布时，列表显示该策略及“待估值”。其已开始日期若被选中且缺少必要值，参考曲线保留缺口。发布后更新当前读数和真实历史，不追填未经确认的早期收益。

策略操作继续走已授权的 CLI／Paseo 路径，Dashboard 保留配置与身份关联，页面读取不会提交模拟盘订单。

**更新能力的验收范围：**发布接口接收调用方已经核对的 v1 投影，不改写数值；新增顶层策略行通过同一接口发布后动态显示。现有总览构建脚本仍绑定本次历史核对范围，后续新策略的核算和持续估值由生产端扩展。上线验收分别记录“新增策略显示与投影发布”和“生产端持续估值”的结果；发布器本身不执行重新核算、券商读取或自动定时任务。

- **已服务页面**：`/`、`/paper` 使用等权比较；`/paper/accounts`、`/paper/history`、`/paper/ledger/{id}`、`/research/overview` 可访问。`/v2/#/paper` 复用相同渲染器。原有报告、研究、系统与旧策略详情入口保留。

- **计算与接口**：本轮相关 Python 测试共 256 项，255 项通过、1 项因样例条件跳过。首次全组发现的新历史锚点断言已修正，随后相关 74 项通过、1 项跳过。7 项浏览器共享计算单元测试通过，覆盖不同本金、移除、单选、空选择、起始日期、缺口及当前快照分离。
- **实际浏览器**：等权均值与独立重算一致；全选、清空、移除 F1、单选 S1、日期滑块、累计／每日／100k 切换及筛选通过。桌面和手机、深浅主题均检查；320、360、390、768、1440 宽度无页面横向溢出。新增图表随窄屏扩大绘图区。
- **状态与详情**：刷新保留策略选择、所选日期与键盘焦点；迟到详情请求不会覆盖后一次选择，关闭后的请求不会重新打开抽屉。关闭抽屉保留当前位置；浏览器返回页面沿用既有导航行为。
