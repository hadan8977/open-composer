## 1. 为什么迭代不智能：根因，不是态度问题

我查了代码本身，而不是凭印象：

1. **代码里的"研究循环"是一台实验执行机，不是研究者。** `open_composer/research/kernel/loop.py` 的核心函数 `run_experiment`
   只做四件事：读一个预先写死的配置 → 跑回测 → 对照预注册门槛打分 → 追加到账本。整个文件里没有任何一处"读历史结果、决定下一步试什么"的逻辑。
   整个 `research/` 目录里，接触 LLM 的只有三个遗留模块（LLM 敞口开关、LLM 轮动、日内轮动），研究内核本身不调用任何模型。
2. **"知识库"只是一个索引，没有人读它。** `reports/research/knowledge/index.json` 有 64 条经验记忆，但没有任何代码或流程在决定下一轮实验时读取它。
   来源卡（文献卡片）同样只是被"绑定"进简报以满足规则，没有被用来选择方法。
3. **智能只在写计划的那一刻存在。** 真正做判断的是我写 Step-N 计划的那几个小时；之后执行者（Codex/Sonnet）按计划跑好几天，不会偏离。
   计划之间的切换只发生在你提意见的时候。这就是你说的"服从项目的要求"：不是执行者服从，是整个流程把判断压缩到了一个点上。
4. **治理是"证明你有资格"，不是"最快学到东西"。** 门槛合同 v2、推广报告、预注册清单、DSR 计数、就绪检查链……每一轮的"成功"被定义成"产出合规的文件"。
   本周为了让 50 只股票的组合进模拟盘，我不得不整条绕开旧的就绪链，这是最直接的证据：那条链保护的是文书，不是钱。
5. **数据模型把"先规则后模型"写死了。** `StrategySpec` 以 entry/exit 规则为源头（项目规则第一条），模型是 Step 11 才作为一种 `portfolio.mode` 挂上去的。
   所以每个候选都是"先有规则框架，再在框架里塞模型"，方法自然千篇一律。
6. **方法单一是计划写死的结果。** 账本里 60 个实验，所有 ML 单元都是同一配方（LightGBM 回归、周频截面标签、前 50 等权）。执行者不会自己换方法，因为计划没说可以。

一句话：**不是模型不够聪明，是系统结构不允许它在实验之间思考。**

## 2. 改成什么样：让 LLM 当研究员，代码当诚实的实验室

你今天的说法是对的：方法选择应该由"LLM + 知识库 + 调研"来判断，而不是我手写一个 10 格网格。那个网格取消。改法如下（这是结构改动，不是再加一条轨道）：

**一个循环，四个动作，每晚或每个会话跑一轮：**

| 动作 | 谁做 | 输入 | 输出 |
|---|---|---|---|
| 读 | LLM | 知识库：实验账本 + 每次实验的"学到了什么"、文献卡、数据清单、一份《当前判断》 | 对现状的理解 |
| 提 | LLM | 上一步 + 你的三层数据框架 + 联网调研 | 3–5 张"假设卡"：要回答什么问题、用哪层数据、预测什么目标、用什么方法、为什么这个方法适合这个问题、预期看到什么、什么结果算否定 |
| 跑 | 代码（现有内核） | 假设卡 | 诚实的结果：点时数据、带隔离期的滚动验证、成本、打乱标签占位、试验次数计入多重检验 |
| 学 | LLM | 结果 | 把"学到了什么"写回知识库；更新《当前判断》；决定下一轮；把值得你知道的用人话讲出来 |

关键差别：
- **判断发生在每一轮之间**，不是每个 Step 一次。方向偏了，最多浪费一晚，不是一周。
- **知识库是被读的，不是被归档的。** 每条实验必须带一句"这个结果改变了我们哪个信念"。
- **门槛从"许可"变成"报告"。** 每个实验都必须报 SPY / MTUM / SPMO / 同波动超额 / 占位对照这五个数，但要不要进模拟盘由《当前判断》+ 你来定，不由合同定。
  （诚实仍然在代码里：点时、隔离、成本、占位、试验计数一个都不少。少的是文书。）
- **方法选择有出处。** 假设卡上"为什么用这个方法"必须引用知识库或文献；这正是你说的"LLM + 知识库 + 调研来判断"。
- **《当前判断》是常设文件**，我每轮更新并主动给你看，而不是等你问。这解决你 9/11 说的"在我说之前你都不会自己去思考"。

落到这个仓库，只加三个命令，不加新轨道：`oc research propose`（读知识库出假设卡）、`oc research run <卡>`（走现有内核）、`oc research learn`（读结果写回知识库并更新判断）。
已有的 60 条账本、64 条经验记忆、来源卡、数据清单都能直接喂进去。外部是否已有现成的这类循环可以直接引入（微软的 RD-Agent 等），见第 5 节的核实结果。

## 3. 为什么"先有策略再做 ML"不合理，正确的顺序是什么

你的直觉是对的，而且这在业界不是新观点。现代做法的顺序是：

**先定目标 → 再定数据 → 再做特征 → 再选模型 → 再做组合 → 最后定执行。策略是这条管道的输出，不是输入。**

| 步骤 | 问的问题 | 我们过去怎么做的 | 应该怎么做 |
|---|---|---|---|
| 目标 | 到底预测什么 | 没单独想，默认"下周收益排名" | 明确选：下周剔除市场后的超额、隔夜收益、是否发生回撤事件、规则信号是否成功……不同目标对应不同问题 |
| 数据 | 信息从哪来 | 只有价格成交量 | 按你的三层：先接一级（内部人、新闻、空头利息），价量只是二级 |
| 特征 | 怎么把数据变成模型能用的列 | 导入五个公开因子库 | 保留，但按目标筛，不追求数量 |
| 模型 | 用什么学 | 一律 LightGBM 回归 | 由目标决定：排序问题用排序学习，事件问题用分类，"接不接受信号"用元标签，体制用无监督；由 LLM 依据知识库选，不是我手写 |
| 组合 | 预测怎么变成仓位 | 前 50 等权 | 由预测置信度和风险决定权重 |
| 执行 | 怎么下单 | 开盘集合竞价 | 已在本周彩排中测量 |

"先有规则策略"只在一种情况下合理：当规则是**基准**（用来证明模型有没有增量）或**约束**（股票池、频率、风险上限）。它不该是模型的容器。
对这个仓库的具体含义：把"模型排名组合"从一种附属模式提升为主模式；规则退为特征或基准；`StrategySpec` 从"规则描述语言"变成"管道容器"（目标 + 数据层 + 模型 + 组合 + 执行）。

## 4. ML 效果怎么提升：什么真正有用，按重要性排

我们自己的证据先摆出来：Step 13 里 4 个 ML 单元全部输给同一批特征上的规则孪生；筛出来的因子集验证 IC 只有 0.035。这个结果本身就是答案：**在同一批价量特征上，模型再换也赢不了规则，因为没有新信息。**

按对结果的影响从大到小：

1. **信息量（数据层）**：新的一级数据带来的提升，通常比所有建模技巧加起来都大。这是为什么下一步是 Form 4 内部人和新闻事件，而不是调参。
2. **目标定义**：预测"剔除市场和行业之后的超额"比预测原始收益稳得多；预测期要和调仓周期一致；很多问题本质是分类或排序，不是回归。
3. **截面设计**：每天把特征按截面排名归一化、对行业和市值中性化、训练验证之间留隔离期。做错任何一条，回测好看、实盘失效。
4. **模型选择**：在表格型截面数据上，梯度提升树是合理默认；线性和树之间的差距远小于前三条带来的差距。深度模型在我们这个数据量上没有优势。
5. **超参数**：影响最小，最容易过拟合，最不值得花时间。

所以"ML 效果怎么提升"的诚实答案是：**先换数据和目标，再谈模型。** 这也是为什么我不再建议在价量特征上开任何新的模型格子。

## 5. LLM + 量化：大家怎么做，LLM 在策略里该放哪

（这一节的外部来源正在由一个后台调研代理逐条核实，结果写在 `reports/research/control/llm-quant-landscape-2026-09-15.md`；核实完成后本节会补上引用和数字。以下是我在核实前的判断，标为【判断】。）

【判断】截至 2026 年，LLM 在量化里有四种用法，证据强度差别很大：

| 用法 | 是什么 | 证据强度 | 对我们 |
|---|---|---|---|
| A. 研究自动化 | LLM 提假设、写因子和模型代码、跑回测、读结果、再提假设（微软 RD-Agent 一类） | 中：有开源实现和论文，但报告的收益多来自 A 股和短样本 | **这正是第 2 节的循环。** 优先看能不能直接引入而不是自己写 |
| B. 文本变特征 | LLM 读新闻、公告、财报电话会，输出情绪、事件类型、新颖度等带时间戳的特征，再交给普通模型 | 强：学术上有可复现的正结果，也是机构实际在用的方式 | 我们已有 2024 年起 68 万篇新闻的点时包，这是现成的入口 |
| C. 挖因子公式 | 让 LLM 在价量算子空间里生成公式 | 弱：多数在 A 股、IC 小、过拟合风险高 | 不做（就是被暂缓的 W4b） |
| D. 智能体直接交易 | 多个 LLM 角色（分析师、交易员、风控）讨论后下单 | 弱：回测短、不计成本、缺少样本外 | 不做直接交易；但"给出理由并记录"的决策日志形式值得借用 |

【判断】机构里的共识大致是：LLM 用来读文本和加速研究，不用来直接预测价格。

**LLM in 策略，具体放在四个位置：**
1. **特征生产者**（用法 B）：每条新闻/公告 → 结构化事件 + 情绪 + 是否新信息，时间戳严格用发布时刻，喂给排序模型。这是最先做的。
2. **体制阅读者**：每周读宏观和市场叙事，输出"当前属于哪种环境"的离散状态，用来门控总仓位。样本短，只做慢变量。
3. **信号裁判**：对规则或模型给出的候选，LLM 结合当日信息说"接受/拒绝/减半"并写理由，理由入库可回溯。这是元标签的 LLM 版本，只在有文本证据时启用。
4. **研究员**（用法 A）：第 2 节的循环本身。

不放的位置：逐笔下单、逐日改参数、在纯价量里挖公式。
