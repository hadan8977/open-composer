1. **`scripts/build_book_v1_alpha.py`**，新文件。输出到 `data/research/equity_book/alpha/book_v1/`：
   - `themes_<year>.parquet`：trade_date、symbol、in_u3000、in_p1000，加 9 个主题分（float32）。主题分 = 主题内 z 列的平均，缺失记 0。主题和列的对应关系照 A1 第 5 节。
   - `formation_ic.parquet`：formation_date、universe（u3000 / p1000）、series（9 个主题名，以及 M0、M1）、ic、n。
     - 形成日 = 会话日历上每月最后一个会话，从信号的第一个月起，到 pos(d)+22 ≤ 最后一个面板会话为止。
     - y = `forward_open_to_open(open, close, p+1, p+22)` − Σ_{k=p+1}^{p+21} X_d·f_k。X_d 用 `RiskModel().at(d)` 的 X，f_k 用 factor_returns 的日因子收益。
     - ic = 宇宙内（in_u3000 或 in_p1000，与 X_d 名单取交集）的 Spearman 秩相关，至少 300 个名字。`RiskModel().at(d)` 抛 KeyError 的形成日跳过，并在汇报里写跳过了几个。
     - M0 序列：等权合成分做秩正态后的 IC。
     - M1 序列：形成日 d 的权重只用 pos(d′) ≤ pos(d) − 22 的主题 IC（最多 60 个、至少 24 个），∝ max(0, 均值/标准差)；不足或全为 0 时用等权。
   - 用 duckdb 或 pyarrow 按年读，只读需要的列。命令：`scripts/run_capped.sh --mem 1.8G -- uv run python scripts/build_book_v1_alpha.py`。

2. **`scripts/run_book_v1_stage2.py`**，新文件。参数：`--plan main|placebo`、`--paths <id,...>`、`--shard`、`--nshards`、`--start`、`--end`、`--out-dir`、`--placebo-seeds`、`--placebo-variants`。
   - **路径编号**：`{variant}_o{offset}_{exec}`，例如 `M0_A_o0_close`。
     - `main` 的固定顺序：先 [M0_A, M0_B, M0_C, M1_A, M1_B, M1_C] × 偏移 0–4 × close，再 [M0_A, M0_B, M0_C] × 0–4 × open，最后 9 条诊断 `M0_A_o0_close_loo_<theme>`（主题顺序照 A1 第 5 节），共 54 条。
     - 诊断路径：合成时去掉该主题，其余 8 个等权；IC_t 用 M0_A 的真实序列；只跑主运行，不做重放。
     - 分片取 `paths[shard::nshards]`。
     - `placebo` 计划：编号 `{variant}_s{seed:02d}_o{seed%5}_close`，只跑主运行、不做重放。本任务**只实现、测试，不运行**。
   - **alpha_source(t, state, universe)**：
     1. 从 themes 表取 t 日 universe 内的主题分；
     2. M0 用等权；M1 在每个月末之后的第一次调仓用 `formation_ic` 里 pos(d) ≤ pos(t) − 22 的主题 IC 重算权重（规则同上），其余调仓沿用；
     3. 加权求和后用 `optimize.rank_normal` 做秩正态；
     4. 安慰剂模式下，在秩正态之后、交给优化器之前，用 `rng = np.random.default_rng(20261001 + seed)`（每条路径开头建一次）对 universe 内的值做 `rng.permutation`，每个调仓日一次。
   - **IC_t**：每次调仓用该变体的 method（M0 或 M1）和 universe（A、B 用 u3000，C 用 p1000）在 `formation_ic` 里取 pos(d) ≤ pos(t) − 22 的最近至多 36 个；不足 12 个时 IC_t = 0.03，否则 IC_t = max(0, 0.5·均值 + 0.5·0.03)。
     - 设置方式：每次调用 decider 前，`decider.spec = op.BookSpec(name, spec.opt.with_(ic=IC_t))`。
     - 安慰剂用同一条真实的 IC_t 序列。
   - **主运行**：`spec = op.BookSpec(name, op.OptConfig(beta_method="ewma", snapshot=exec))`，`op.make_decide(alpha_source, RiskModel(), spec, attrs=PanelAttributes(), etf_risk=ETFRisk(rm), eligibility=op.ShortEligibility(panel))`；`cfg = op.book_config(spec, attrs, freq="W", offset=k, exec_price=exec, start="2017-10-02", end="2026-09-17", initial_weights={TBILL: 1.0}, initial_equity=1_000_000.0, snapshots=False)`。
     - 用一个包装函数记下每个调仓日 decide 的输出：dict 记为目标，None 记为失败日。
   - **4 个重放**：`signal_dates` 取主运行的全部调仓日；decide 返回存下的目标，失败日返回 None。
     - cost2x：`cost_fn` 是把 `make_cost_fn(snapshot_for(exec))` 的三项都乘 2 的包装，`borrow_bp_per_year=100`；
     - fix10、fix20：`cost_fn=None`，`cost_bp_per_side=10` 或 `20`，借券同主运行；
     - delist30：模型成本，`delist_long_haircut=-0.30`。
   - **每条路径写到 `<out-dir>/<path_id>/`**：
     - `daily.parquet`：主运行的 `BookResult.daily` 全部列；
     - `targets.parquet`：长表 decision_date、symbol、weight，含 TBILL；
     - `failed_dates.json`；
     - `records.parquet`：`decider.records`，复杂字段转成 JSON 字符串；
     - `replays.parquet`：日期 × net_cost2x、gross_cost2x、net_fix10、net_fix20、net_delist30；
     - `meta.json`：path_id、variant、offset、exec、各段耗时、调仓次数、最终失败数、第一次尝试失败数、各级救回次数（从 records 的 attempt 字段统计）、IC_t 的最小/中位/最大值和取先验的次数、M1 每次更新的权重，以及容器里 A1 绑定文件的 sha256。
   - 本脚本不计算任何夏普或收益统计。
