# T-20261002-40 brief: held names that no longer trade must not block the whole plan (frozen positions)

Coordinator code: **R1002-0736-T40**. Every later message to this agent starts with it.
Written 2026-10-02 07:36 UTC by the interactive lead (Opus).

## Why
The T-28 engine replay (`reports/research/iterations/t20261002_book_v12/engine-replay.json`, commit 6014b82) runs the primary variant M0_U3000 over 60 sessions. On 18 of them, each account's plan is blocked by `reference_prices_complete`.
- In every case a name the account still holds has no close on the decision date D.
- Of the 23 events, 22 are names that stopped trading (cash acquisitions, mergers, delistings; last close is D−1). One (ARTL) misses a close on D and trades again later.
- `build_plan` refuses the whole plan if any held or target name lacks a reference price. In production every acquisition would therefore stop trading for one or more days. This must be fixed before the paper start condition "two consecutive green dry-run sessions" can be met.

What Alpaca does, which the fix must respect:
- After a cash acquisition or delisting, the position stays in the account for a few days at its last price, with the asset `tradable: false` (or status inactive). Then the broker converts it to cash, or to acquirer shares for a stock merger.
- Orders on such an asset are rejected.
- `GET /v2/positions` reports `current_price` and `market_value` for every position, including these.

## Steps
1. **Read first.**
   - Read `plan.py` (`AccountState`, `AssetInfo`, `read_account_state`, `make_asset_lookup`, `build_plan`, `_risk_checks`, `RiskLimits`, `OrderPlan`), `tests/test_book_paper.py`, `tests/test_book_paper_hedge.py`, the replay script and the `explanations` block of `engine-replay.json`.
   - Run `uv run pytest -q tests/test_book_paper.py tests/test_book_paper_hedge.py tests/test_book_v12_targets.py` and record the baseline count.
2. **Account state.**
   - `AccountState` gets `position_prices: Mapping[str, float]`. It defaults to empty (`field(default_factory=dict)`), so every existing caller and test is unchanged.
   - `read_account_state` fills it from each Alpaca position's `current_price`. If that is missing, use `market_value / qty`. If neither exists, skip the name.
   - Reads only.
3. **`RiskLimits`** gets `max_frozen_gross: float = 0.02` (fraction of the equity basis). No existing limit changes.
4. **`build_plan`.** For each held symbol with no entry in `target.reference_prices`, call `asset_lookup` once and classify it:
   - **frozen**: the lookup returns `None`, `tradable` is false, or `status` is not `active`.
     - No order.
     - `post_qty` stays at the held quantity.
     - Valued at `position_prices`. If there is no price, the name is "unvalued".
   - **close-out**: tradable and active, with a target weight of 0 or absent.
     - Order the full position (delta = −current).
     - Use `position_prices` as the reference price, and record `reference_price_source: "broker_position"` on the order row.
     - The usual $100 minimum, the easy-to-borrow rule (it cannot apply to a buy-to-cover) and `time_in_force=cls` apply.
     - If there is no broker price, the name stays unpriced.
   - **unpriced** (blocking, as today): a name with a nonzero target weight and no reference price, or a close-out name without a broker price.
   - `reference_prices_complete` then counts only unpriced names. Its detail lists them.
   - New check **`frozen_positions`**:
     - value = Σ |qty × price| / equity basis over frozen names;
     - limit = `max_frozen_gross`;
     - it fails if the value is over the limit or any frozen name is unvalued;
     - the detail lists each frozen name with its quantity, price, value and reason.
   - Frozen names are left out of the stock-overlay checks: `net_dollar`, `gross_stock`, `max_name_weight`, `beta_neutral` and `exposures_complete`. They cannot be traded, and acquired names are economically cash.
   - `gross_leverage` includes them at the broker price, because Reg T counts them.
   - The plan payload gets a `frozen` list, empty when there are none. A plan with no frozen or close-out names must serialize exactly as before.
5. **Replay.**
   - The fake `AccountState` gets `position_prices`: for each held name, the last close ≤ D in the data.
   - The fake `asset_lookup` returns `tradable=False, status="inactive"` for a held name whose last close in the data is before D and that never trades again in the snapshot. A name that misses D but trades later (ARTL) is tradable.
   - Removal assumption, to be stated in the JSON: the broker removes a frozen position, converting it to cash at its last close, after 2 sessions frozen. Keep the old assumption's result as a comparison field.
   - Re-run the 60 sessions for the primary, both accounts, plus the `other_variants_summary`.
   - Report blocked days, frozen events, the maximum frozen gross, and the close-out orders.
   - Also quantify the parity gap T-28 left: on each day, the summed |contract target weight| of target names the generator dropped (no close on D). Report the median and the maximum.
6. **Tests** (`tests/test_book_paper_frozen.py`, at least 10, fake client only):
   - a frozen long and a frozen short under 2% produce no order and pass;
   - frozen gross over 2% fails `frozen_positions`;
   - an unvalued frozen name fails it;
   - a tradable held name without a reference price and with target 0 becomes one full close-out order at the broker price;
   - a close-out under $100 is dropped like any other;
   - a target name with weight ≠ 0 and no price still blocks `reference_prices_complete`;
   - frozen names are excluded from `beta_neutral`, `net_dollar`, `max_name_weight` and `exposures_complete`, and included in `gross_leverage`;
   - `read_account_state` fills `position_prices` from a fake client (including the `market_value / qty` fallback);
   - a plan without frozen names is byte-identical to the current output on an existing fixture;
   - the ARTL-like case (tradable, missing on D) becomes a close-out, not a freeze.
