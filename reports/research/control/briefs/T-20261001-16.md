# T-20261001-16 brief: short-capable portfolio order engine for the equity book (dry-run only)

Written 2026-10-01 17:33 UTC by the interactive lead (Opus). Coordinator code in the launch message.

## Why
The owner opened two Alpaca paper accounts on 2026-10-01: quant1 and quant2, USD 1M each. The authorization and its scope are in `reports/research/control/owner-authorization-2026-10-01-book-paper-accounts.md`; read it first.

The equity book is a 100-250 name long/short, dollar- and beta-neutral portfolio rebalanced weekly at the closing auction. The existing paper engine cannot run it:
- `open_composer/paper_rehearsal.py` line 296 requires `position_direction == "long_only"`;
- `open_composer/adapters/broker/alpaca_paper.py` submits per-signal orders for ETF sleeves.

## Deliverable
A new package `open_composer/book_paper/` with tests, and a CLI entry. Everything works end to end in dry-run.

### 1. Accounts
- Each account name maps to environment variables: `ALPACA_BOOK_BASE_URL`, `ALPACA_<NAME>_API_KEY_ID`, `ALPACA_<NAME>_API_SECRET_KEY` for NAME in {QUANT1, QUANT2}.
- Load them with `dotenv_values` from the path in `OC_BOOK_ACCOUNTS_ENV`, default `/root/.config/open-composer/paper-book-accounts.env`.
- Hard guard: the base URL must contain `paper-api.alpaca.markets`, otherwise raise.
- Never print, log or persist any credential value. Write a test that scans written artifacts for the key prefix pattern.

### 2. Inputs
- A target file per account and decision date, `reports/paper/book/<account>/targets/<YYYY-MM-DD>.json`, holding:
  - book id (contract and variant, e.g. `t20261001_book_rf1:RF_M0_A`);
  - form, F1 or F2;
  - decision date t and execution date (the close of t+1);
  - equity basis;
  - weights {symbol: fraction of equity}, including the T-bill leg (SGOV or BIL) for F1, or SPY 1.0 for F2;
  - the risk-model exposures needed for checks: per-name beta, industry and size;
  - a SHA-256 of the payload.
- The target file is written before any order: this is the "signal logged before order" rule. Provide a writer function.
- F2 conversion: F2 weights = F1 stock overlay weights + SPY 1.0 in place of the T-bill leg. Implement it as a pure function and test it.

### 3. Order plan for the execution date
1. Read broker positions and account equity (read-only).
2. Target shares = weight × equity basis / reference price. Use the last close, passed in; no network price in tests.
3. Round to whole shares, longs and shorts alike. CLS orders are whole-share, and shorts cannot be fractional. Drop orders under a minimum notional, default 00, and report the rounding drift.
4. Before any order that opens or increases a short, check `easy_to_borrow` (GET /v2/assets/{symbol}). Names that fail are removed from the plan and reported; the residual exposure is re-checked. Never "replace" a name inside the engine — that is the optimizer's job.
5. Pre-trade risk checks on the post-trade book; failing any check blocks the whole plan, never trims it silently:
   - |net dollar| ≤ 5% of equity for F1;
   - gross stock exposure ≤ 1.05 × target gross;
   - every name ≤ 1.25% of equity;
   - long + short + T-bill ≤ 1.98 × equity, under the Reg T overnight 2× with a buffer;
   - |Σ beta·w| ≤ 0.05;
   - data freshness: the target decision date must be the previous session;
   - the kill switch: reuse `_require_kill_switch_clear` semantics from `alpaca_paper.py` or the same file it reads.
6. Orders are market-on-close: `time_in_force="cls"`, type market.
   - Submission window: before 15:50 ET. The engine refuses at or after 15:45 ET to keep a margin, and refuses before 09:30 ET on the execution date.
   - Deterministic `client_order_id` = hash(book id, account, execution date, symbol, side, qty). Before submitting, look up existing orders by `client_order_id` (idempotent: no duplicates on re-run).
7. `--submit` is required to send anything. Without it, the plan is written to `reports/paper/book/<account>/plans/<date>.json` and nothing is sent. **In this task `--submit` must stay unused.** Implement the code path, but test it only against a fake client.

### 4. After the close
- **Reconcile**: orders → fills → positions. Report unfilled orders, partial fills and position drift against the targets.
- **TCA**: fill price against the official close (for CLS they should match) and against the 15:45 snapshot proxy.
- **Shadow costs** from cost model v1 (`open_composer/research/equity_book/costs.py` / `costfn.py`): half-spread at the close snapshot, impact at the traded size, plus borrow at 25 bp a year on short notional. Paper fills include neither impact nor borrow fees.
- **Daily P&L**: gross from the broker; net = gross − shadow costs. Record the beta and the exposures realised.
- Output: `reports/paper/book/<account>/daily/<date>.json`.

### 5. Exit rules
RF1 `hypotheses.md` section 7 and `addendum-1-track-record.md`, computed on a supplied daily net-return series. Implement it as a pure function returning one of: continue, halve, stop.

### 6. CLI
Add `oc book-paper` in `open_composer/cli.py`. Keep it small and follow the existing typer patterns. Subcommands:
- `plan` (dry-run plan from a target file);
- `submit` (requires `--submit`; not exercised);
- `reconcile`;
- `status` (read-only account summary, without the account number or keys).
