## 为什么做

第二版计划第 3.5 节第 3 条、第 2 节第 4 条，以及 P-1、P-4：深挖和进化式搜索都会大量增加试验，最容易自欺。借 autonomous-quant-researcher 和 Qanat 的做法（`reports/research/intel/I-20261004-08-vibe-trading-wave-since-2026-08.md` 第 6 节），在我们自己的门里补四项。**已有的不重做**：试验台账、候选编号去重、最终评估回执、锁箱。

门的代码在 `open_composer/research/iteration_dossier.py`（`validate_iteration_dossier`、`require_iteration_execution_gate`），命令是 `uv run oc research iteration validate <iter> --stage <pre-backtest|final>`；仓库检查是 `uv run oc repo check --strict`。

## 四项

1. **跨项目试验总数**：新建追加式 `reports/research/trials.jsonl`，每行一个试验（项目、迭代 id、候选 id、机制族、登记时间、是否规模曲线上的点）。
   - 从现有各迭代的清单和 `trial-ledger.json` 回填，只记数，不改原档案。
   - 新命令 `oc research trials count [--family F] [--program P]`。
   - `iteration validate --stage final` 的输出里报该族的累计试验数，DSR 用它（而不是只用本迭代的数）。
2. **语义查重和族配额**：pre-backtest 阶段，把新候选的机制描述和已有方向、已有候选比对（本地方法即可，例如归一化后的词集相似度或 TF-IDF 余弦；不调用外部接口和大模型）。
   - 相似度超过阈值的，要求档案里写明差异，否则判阻断。
   - 族配额：每个机制族每月新增候选数的上限，放进 `config/` 下的配置（初值 30），超出判阻断，除非档案里有主审轮签字的例外记录。
3. **盈亏平衡成本**：final 阶段要求每个候选报单边盈亏平衡成本（基点），即净夏普或净超额为 0 时的单边成本，由毛收益和换手算出。缺这个字段判阻断。
4. **门槛变更留痕**：
   - pre-backtest 冻结时，把 `config/evaluation-standard-v2.json` 的 sha256 记进档案；
   - 新建追加式 `config/evaluation-standard-changelog.jsonl`，每行：哈希、日期、谁改的、为什么、主审签字；
   - final 阶段，标准文件的哈希和冻结时不同、且变更记录里没有覆盖新哈希的条目，判阻断；`oc repo check --strict` 在当前哈希没有变更记录时失败；
   - **初始化**：变更记录先写两条——变更前的版本（取 git 里 10-05 改动之前那一版的哈希，标"初始登记"），和 2026-10-05 的改动（V2 整股可行性量化，交互会话 Opus，来源 T-20261004-71 和第三轮复核 review-3.md 第 3 条；签字"交互会话 Opus（主审）"）。
