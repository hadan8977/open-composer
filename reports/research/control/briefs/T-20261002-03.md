目标：为 U3000 公司建 10-K 文本变化数据：每份 10-K 和上一份 10-K 的相似度，分全文、Item 1A 和 Item 7 三节，每节算余弦和 Jaccard。可见时间按 EDGAR 的 acceptanceDateTime 记。这是 `reports/research/iterations/t20261002_lazy_prices_ic/` 的数据步骤；**本任务不计算任何 IC，不看收益**。

背景：
- 组合 v1 的停止条件已成立，要先补信号。文本变化（Lazy Prices）是纲领候选清单 v2 的第一项，免费，不需要大模型。
- 预注册已冻结在 `reports/research/iterations/t20261002_lazy_prices_ic/hypotheses.md` 第 2 节，本任务的数据规则全部照它，不许改。
- 先只读该文件第 2 节（`sed -n '/^## 2/,/^## 3/p'`）。不要读第 4–5 节以外的结果类文件，也不要读任何收益数据。

输入：
- 研究面板：`data/research/equity_book/panel/{2016..2026}.parquet`，只读。用到的列是 trade_date、symbol、in_u3000。
- symbol→CIK：`data/features/sic_map/sic_map.parquet`，列为 symbol、cik、link_first_date、link_last_date。
- 申报索引：`data/raw/sec_submissions/submissions.zip`（1.5 GB）。读法复用 `scripts/build_sec_sic_map.py` 的 `read_bulk_records(zip_path, ciks)`、`is_cik_member`、`member_name`。
- SEC 客户端：import `scripts/collect_sec_13d_filings.py` 的 `SecClient`，按该文件第 875 行的方式 `load_dotenv(dotenv_path=ROOT / ".env")`，`min_interval=0.125`（每秒 8 次，SEC 上限是 10 次）。
- 时点映射：import `scripts/build_h20260928_16_sentiment_accel_feature.py` 的 `attribute_trading_day`；交易日历用研究面板里的 trade_date。

步骤：
0. **前置**，任一不满足就保持 `ready`，在 notes 写原因后结束：
   - `df -h /` 剩余 ≥ 4 GB；
   - 当前 UTC 不在 21:30–00:30（不和模拟盘的定时任务抢机器）；
   - `pgrep -fa 'run_capped|build_|update_sip_archive|modal run' | grep -v pgrep` 没有输出。有输出就按 540 秒一段前台等，最多 30 分钟。
1. **新脚本** `scripts/build_10k_text_similarity.py`，子命令如下：
   - `universe`：
     1. 取面板里 in_u3000 为真的 (symbol, trade_date)。
     2. 每个 (symbol, 日期) 映射到 CIK：只看跨度 ≥ 180 天的链接，覆盖该日期的链接里取跨度最长的一条。sic_map 里有一天长的误链，例如 A→1823406。
     3. 输出 `data/features/text_similarity/cik_map.parquet`，列为 symbol、cik、first_date、last_date，按连续区间合并。另输出 CIK 清单。
   - `index`：
     1. 从 submissions.zip 读这些 CIK 的申报。`filings.recent` 没覆盖到 2014-07-01 的，还要读该 CIK 的分页成员 `CIK##########-submissions-###.json`。
     2. 只留 form 恰好等于 `10-K`、filingDate 在 2014-07-01..2026-09-30 的。
     3. 输出 `.../filings_index.parquet`，列为 cik、accession、filing_date、acceptance_datetime（UTC）、report_date、primary_document、url。URL 格式是 `https://www.sec.gov/Archives/edgar/data/<cik 整数>/<accession 去掉横线>/<primaryDocument>`。
     4. 先用 AAPL（CIK 320193）手工核对一行，确认格式。
   - `fetch`：
     1. 主进程单线程顺序抓取。用 `concurrent.futures.ProcessPoolExecutor(max_workers=2)` 解析；每份 HTML 解析完立即丢弃，**不落盘任何 HTML 或全文**。
     2. 解析规则逐条照 hypotheses.md 第 2 节：
        - lxml 转文本，去掉 `ix:header`、隐藏元素和全部 `<table>`；
        - 分节取全文、1A（止于 1B 或 Item 2）、7（止于 7A 或 Item 8）；
        - 条目标题在目录里重复出现时，取后面正文最长的一处；
        - 分词：小写，2–20 个字母，不做词干化，不去停用词。
     3. 每份申报返回三节的词频 Counter 和词数。
     4. 一个 CIK 的全部 10-K 解析完后，按申报日排序，相邻两份间隔在 300–430 天之间的才配对。每对算三节的 `cos`（原始词频余弦）和 `jac`（词集合 Jaccard）；某节少于 50 个词就记缺失。
     5. 断点：每完成 100 个 CIK，写一个 `.../_parts/part_<序号>.parquet`，并在 `_progress.json` 里记录已完成的 CIK。`--resume` 跳过已完成的 CIK。
     6. 单次运行超过 `--max-minutes`（默认 120）就在 CIK 边界停下，退出码 3。
     7. 404/403/解析失败只记 `fetch_status` 和 `parse_status`，不重试超过 3 次，不中断整体运行。
   - `merge`：把 parts 合成两张表。
     - `.../10k_filings.parquet`：每份申报一行，列为 cik、accession、filing_date、acceptance_datetime、visible_day（`attribute_trading_day`）、n_words_full/rf/mda、rf_found、mda_found、fetch_status、parse_status。
     - `.../10k_pairs.parquet`：每个配对一行，列为 cik、accession、prev_accession、filing_date、prev_filing_date、gap_days、visible_day，以及 cos_full、cos_rf、cos_mda、jac_full、jac_rf、jac_mda。
     - 再写 `_manifest.json`：参数、行数、各状态计数、起止时间、代码的 git 哈希。
2. **测试** `tests/test_build_10k_text_similarity.py`，不联网，用手写的小 HTML，覆盖：
   - 目录里有重复的 Item 1A 标题时，取正文最长的那一处；
   - 1A 止于 1B，7 止于 7A；
   - `<table>` 和 `ix:header` 被去掉；
   - 余弦、Jaccard 的数值（手算的小例子）；
   - 300–430 天的配对边界；
   - 不足 50 词记缺失；

   - 命令：`uv run ruff format <新文件>`、`uv run ruff check <新文件>`、`uv run pytest -q tests/test_build_10k_text_similarity.py | tail -5`。

   - 打印这 20 个 CIK 的配对数、cos_full 的中位数。
   - 不对就修解析，再试跑，最多三次。还不对就停下，标 `blocked`，写清哪种文档结构解析不了。

   - 按 540 秒一段前台等。
