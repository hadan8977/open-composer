# T-20261002-27 brief: paper engine hedge leg and variable T-bill leg for book v1.2 (dry-run only)

## Why
Book v1.2 (`reports/research/iterations/t20261002_book_v12/hypotheses.md`, section 3) holds:
- **F1 (quant1):** dollar-neutral stocks (long ≈ 0.5, short ≈ 0.5), plus a **SPY beta hedge** of about 0.25–0.65× equity (long SPY, because the stock legs have negative beta), plus a **T-bill leg** (SGOV) of size x in [0, 1], where x = max(0, min(1.8 − L − S, 1 − L + S)).
- **F2 (quant2):** SPY core 1.0, plus a stock overlay of about 0.3, plus that overlay's SPY hedge, merged into one SPY position (total SPY = 1.0 + hedge).

The engine built by T-16 (`open_composer/book_paper/`, commit e618915) cannot express either form:
- `BookTarget` requires the core weight to be exactly 1.0 (`CORE_WEIGHT_TOLERANCE`).
- The pre-trade checks treat every non-core symbol as a stock. `net_dollar` (≤ 0.05), `max_name_weight` (≤ 0.0125) and `beta_neutral` (stock overlay only, ≤ 0.05) would all reject the SPY hedge.

This task extends the engine so it can carry these forms. It does not generate v1.2 targets. The target generator is a separate later task: it imports the contract logic that T-20261002-26 is writing in `open_composer/research/equity_book/book_v12.py`.

## Steps
1. **Read first:** read the four modules and `tests/test_book_paper.py`. Run `uv run pytest -q tests/test_book_paper.py` and record the baseline count.
2. **`BookTarget` schema version 2**, backward compatible: every existing v1 target file and test must still load and behave the same.
   - New optional fields:
     - `core_weight: float = 1.0`. F1 allows [0, 1]; F2 requires exactly 1.0.
     - `hedge_symbol: str | None = None`. Only `SPY` is allowed for now.
     - `hedge_weight: float = 0.0`. Must be finite and |hedge_weight| ≤ 1.5.
   - `weights` keeps one entry per symbol, the merged position used for orders.
     - The core entry equals `core_weight`, plus `hedge_weight` when the hedge symbol is the core symbol (F2).
     - For F1, the SPY entry equals `hedge_weight`.
     - Validate these identities to 1e-9.
   - `stock_weights` (and therefore `target_gross`) excludes both the core and the hedge symbol.
   - Add `hedge_weight` to the canonical payload hash. Adding the new fields must not change the hash of a v1 target. Test this with a fixed v1 fixture that has a known hash.
   - `f1_to_f2_weights` and `convert_f1_target_to_f2` keep their current behaviour for v1 targets. They refuse to convert a target that has a hedge; v1.2 F2 targets are generated directly.
3. **Pre-trade checks in `plan.py`**:
   - `net_dollar`, `gross_stock`, `max_name_weight` and `exposures_complete` run over the stock overlay only, excluding the core and the hedge.
   - `beta_neutral` = Σ β_i w_i over the stocks + 1.0 × hedge weight (as executed after rounding). The limit is still `max_abs_beta`. The detail text says that the hedge is included.
   - `gross_leverage` = Σ |merged position weights| over all symbols after rounding, including the core and hedge. The limit is still 1.98.
   - New check `core_leg`: for F1 the post-trade T-bill weight is within ±0.02 of `core_weight`; for F2 the post-trade SPY weight is within ±0.02 of 1.0 + `hedge_weight`.
   - Order generation is unchanged: whole shares, `round_half_away`, $100 minimum, and the easy-to-borrow filter for opening or increasing shorts. SPY and SGOV are never shorted in these forms.
4. **Tests** (`tests/test_book_paper_hedge.py`, at least 10, no network, fake client only):
   - an F1 v2 target with 6 stocks (dollar-neutral, beta −0.7 × 0.5), SPY hedge +0.35 and SGOV 0.45 passes every check; without the hedge `beta_neutral` fails;
   - a hedge sign error fails `beta_neutral`;
   - an F1 core above 1.0 is rejected by validation;
   - F2 v2 with SPY 1.0 + 0.2 merged builds one SPY order and passes `core_leg`;
   - an F2 core weight other than 1.0 is rejected;
   - gross leverage 2.05 is blocked;
   - v1 fixtures load with an unchanged hash;
   - the order count and notional for a toy book match a hand computation;
   - `max_name_weight` ignores SPY and SGOV;
   - `submit_plan` refuses outside the window (existing behaviour, still covered).
5. **Dry-run on a real-looking target**: build an F1 and an F2 v2 target in a temporary directory, with about 200 synthetic names and prices taken from `data/research/equity_book/etf_daily.parquet` for SPY and SGOV (read-only). Run `build_plan` with a fake `AccountState` (empty positions, equity 1,000,000) and print the check table into your report. **Do not create a broker client and do not call any API.**
6. **Finish:**
   - Run `uv run ruff format` and `uv run ruff check` on your files, then `uv run pytest -q tests/test_book_paper.py tests/test_book_paper_hedge.py`; all must pass.
   - Commit only your files with `git commit -- <paths>`, after checking `git diff --cached --name-only`. The message starts with `feat: T-20261002-27`.
