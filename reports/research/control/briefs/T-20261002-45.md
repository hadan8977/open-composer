## 1. `scripts/pm_release_shadow.py` (forward evidence for the parked H1)

### `signal` subcommand

- Find Kalshi macro events (series as in the collector) whose release day T is the **next NYSE session** after today (ET).
- **Window guard:** run only when the current ET time is between 15:00 and 15:50 on T-1. Outside that window, exit 0 and write nothing, with a message. Cron calls it at both 19:10 and 20:10 UTC so one call lands in the window across the DST change.
- For each event, fetch hourly candles up to the candle ending at or before 15:00 ET today. Compute U and U_rel exactly as the builder does:
  - U_rel uses the previous 12 events of the series from `data/research/prediction_markets/kalshi/release_uncertainty.parquet`, plus earlier forward rows.
  - Day-level signal = max U_rel across the day's releases.
  - `would_hold` = day-level U_rel > 1 and the day is not FOMC-only, mirroring candidate U1.
- **Output:** append one JSON line per event and one per day to `data/features/prediction_markets/h1_shadow/signals.jsonl`.
  - Fields: `logged_at_utc`, `release_date`, `series`, `event_ticker`, `n_usable_strikes`, `pmf_mean`, `U`, `U_rel`, `day_U_rel`, `would_hold`, `code_commit` (`git rev-parse HEAD`).
  - Never rewrite earlier lines.
  - If an event for that release day is already logged, skip it.

### `realize` subcommand

- For each logged release day with T at or before the last date in `data/sip/daily`, append realized excess returns to `h1_shadow/realized.jsonl`.
  - QQQ, SPY and IWM R_cc and R_co, plus BIL, as defined in the iteration's hypotheses.md.
  - Skip days already realized.
- Read SIP daily read-only, the same way the T-44 test script does.

### `summary` subcommand

- Print the forward-only count of release days.
- Print D (`would_hold` minus not), as in H1.
- Print the count still needed to reach 60.
- This is **no decision**: label it `forward_only_no_decision`.

### Tests

Use fake candles and fake SIP frames:

- the window guard;
- no candle after 15:00 ET T-1 is used;
- U_rel uses only prior events;
- idempotent appends;
- `realize` maps T-1 close to T close correctly;
- FOMC-only days are not `would_hold`.

## 2. `scripts/pm_digest.py` (daily odds digest for the owner)

- Read the latest hourly snapshots in `data/features/prediction_markets/kalshi_hourly/` and `polymarket_hourly/`.
- Write `data/features/prediction_markets/digest/YYYY-MM-DD.md` in plain Chinese, at most about 40 lines. It contains:
  1. **Polymarket watchlist by group:** current yes price, change versus the snapshot nearest 24 h and 7 d earlier (when available), and volume.
  2. **Kalshi:** upcoming macro releases in the next 10 sessions, each with the implied mean and std from the latest snapshot, and U_rel when computable.

- No trading language: this is research and decision support only, and it says so in one line at the top.
