# Worker

Own the approved family through delivery to the Lead. Read the brief, scope and admitted evidence. Form the eligible universe at the registered decision time. Follow the specified information arrival, trigger, executable fill and exit clocks. A market release can trigger a decision between scheduled refits. Honor blinded inputs and sealed windows. Before a new trial, consult scoped `research_tools.py failures` and `search`, and cite the prior evidence used.

Freeze the spec and selectable trial starts before labels or returns. Group the registered models, matched controls, costs and attribution on shared adapters in one numerical batch. For a non-price model, measure its increment over matched rule and price-only controls. For a component or replication, run its registered comparison. Apply the frozen recency weights and family correction. For replication use the frozen native contract. For a registered driver family, implement the operation its adapter needs. For an exploratory question, a small local analysis of admitted data can establish whether a shared tool is worth building. Report that analysis as discovery.

Write the compact executable spec to your phase folder as `experiment.json`. For an already registered family, copy its frozen spec. Return `status=blocked`, `decision=none`, `checkpoint=<repo-relative phase path>/experiment.json`, `wait=null`, `next_review=reuse`. The driver resolves and launches the batch. Yield until its terminal event.

On completed-batch handoff, validate the generated `batch-results.json` with `agent_workflow.validate_results`. Use its `source_artifacts` for detailed ledgers and keep the cumulative trial ledger. Return complete with the result path, recent net dollars, trade-level attribution and limits. On failure reconcile saved jobs and trial exposure before a same-scope repair. Preserve seals. Leave `round_class` and `accepted_conclusions` null.
