# Uncodixfy

Make task interfaces clear, efficient, and coherent. Follow the [local skill map](../impeccable/reference/skill-map.md); use impeccable for an open visual direction or a broader redesign.

## Understand the task

Read the target and surrounding layout. Identify the primary action, information users compare, frequent actions, current state, and recovery needs. Distinguish visual clutter from useful information density.

Keep existing product language, components, tokens, and recognizable identity unless a redesign was requested. References such as Linear or GitHub illustrate interaction economy; they are not templates to clone.

## Simplify relationships

| Area | What to improve |
| --- | --- |
| Navigation | Clear location and labels, useful grouping, predictable selection, and an appropriate narrow-screen arrangement |
| Headers and toolbars | A meaningful title and actions at the correct scope; remove repeated promotional explanations from operating screens |
| Lists and tables | Align comparable data; make selection, sorting, status, and row actions easy to scan |
| Forms | Visible labels, useful grouping, relevant help, clear validation, and recoverable errors |
| Controls | Stable geometry, legible enabled/disabled states, timely feedback, visible keyboard focus, and adequate touch targets |
| Panels and dialogs | Group or elevate content for a reason; avoid wrappers that add emphasis without separating tasks |
| Density | Preserve useful context and scanning; remove arbitrary gaps without crowding content |
| Motion | Explain selection or state without delaying actions; respect reduced motion and interrupted interaction |

Repeated shells, shadows, badges, and icon backings deserve inspection when they compete for attention. Keep them when they communicate a meaningful distinction. A status count or quota indicator is functional information when the task needs it.

## Keep the chosen style

Use a consistent type hierarchy, spacing system, color roles, and control language. Derive dimensions from content, platform, and the established system; do not impose fixed sidebar widths, radius caps, font bans, or random palettes.

System fonts, blue accents, pill controls, sliding indicators, and dimensional materials can all be appropriate. Judge whether they remain readable, recognizable, and usable in this interface. Preserve intentional expression while removing redundant emphasis.

Do not add a hero, fake metrics, decorative dashboard, or extra sidebar merely because a template contains one. Do not remove an existing useful structure solely because it is common.

## Verify

Inspect the affected screen with realistic content and its main task. Check narrow layouts, keyboard focus, and the states touched by the change. Report the concrete improvement and any unverified behavior. Stop at the requested scope.
